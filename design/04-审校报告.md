# 04 · 第二轮审校：矛盾、可提升点与需要拍板的决定

> 对象：`01-视觉语言.md`、`02-页面与交互.md`、`03-Agent发布架构.md`、`design/README.md`、`design/prototype/`（21 张截图、`assets/*`、`shoot.mjs`），以及本地 Mochi UI 1.4.3 源码。

## 2. P0 · 现在必须裁决（9 条）

### P0-1 「一份 canonical + 六语 UI」在静态站下不成立

- 位置：`02:24-26`（文章只有一份 canonical，不按语言复制；语言切换只影响 UI 文案；hreflang 标在文章页）+ `02:382-384`（文章页 UI 文案取 cookie `stide_locale`，切换后文章页「保持原地只换 UI」）+ `01:252-253`（UI 语言跟随偏好，可与文章 lang 不同）。
- 冲突：静态 HTML 一个 URL 只有一份文案。cookie 驱动的 UI 语言意味着要么同 URL 有 6 份（不可能），要么客户端换词（闪一次 + SEO 无意义），而 `<html lang>` 又已经钉死给文章——hreflang 指向自身没有意义。
- 建议定为（v1）：**文章正文语言 = 页面唯一语言；文章页 UI 固定 `zh-CN`。** 语言切换只存在于壳页；在文章页点语言，跳到对应壳页首页（不做原地换词）。把「文章页 UI 不翻译」写进 02 §15 与关于页，作为公开限制。v1.1 若要真六语，走 `/en/p/<slug>/` 六份 + `canonical` 指向 `/p/<slug>/` + hreflang 集群——那时「一份 canonical」要改写成「一份 canonical，多份副本」。

### P0-2 Pagefind 分索引 = 非中文壳页搜不到文章

- 位置：`02:273`（只索引文章正文）+ `02:381-382`（壳页六语、文章 `<html lang>` 随文章）。
- 冲突：Pagefind 按页面 lang 建索引，搜索端按当前页 lang 选索引。文章几乎全是 `zh-CN`；用户切到 `/en/` 后搜索端加载 en 索引 → 0 结果。日/俄/韩同理。这是「搜索是核心功能」的直接失效。
- 建议定为：**索引侧 `force_language: zh`，全站单索引**；我们自绘面板，不依赖 Pagefind 的 UI 翻译。中文查询在 1.5 已有分词（`高达` 可命中）。同时在 02 §8 加一条：搜索覆盖所有语言文章，与 UI 语言无关。

### P0-3 「人格 = 色相」只改 `--mc-h`，改不动强调色

- 位置：`01:70`（「Mochi 的 `--mc-h` 是整套界面的单一色相源」）+ `01:339-340`（运行时注入 hue）+ `01:322-336`（`stide` pack）。
- 事实：Mochi 是三轴——`--mc-h` 主、`--mc-h2` 强调、`--mc-h3` 渐变尾；按钮、链接、选中态读的是 `--mc-h2`（`tokens.css:75-79`、`:499` 起）。原型同样只在 `index.html:2-3` 定了一次 `--mc-h2: 232`，之后只改 `--mc-h`（`assets/app.js:135-139`）——所以原型里换人格，强调色其实没换。
- 建议定为：人格注册表给一个 `hue`，前端派生三轴：`h2 = h`、`h3 = h - 34`（或 `+34`，按纸面亮度选一边），三轴一起过渡（Mochi 自带 `--mc-hue-transition`）。`01 §3` 的「单一色相源」改成「单一 hue 输入，派生三轴」。

### P0-4 玻璃层级与参数三处打架，且 `stide` pack 从未生效

- 位置：`01:30-31`（L2 = 设置抽屉 + 搜索面板，blur 20 / 纸色 72%；L3 = Dialog，blur 28 / 86%）↔ `02:264`（搜索浮层 L3）↔ `02:285`（设置抽屉 L3）↔ `01:64`（暗色 blur 20→14）↔ `01:330-335`（`--mc-blur: 12px`、`--mc-blur-lg: 20px`、`--mc-glass-alpha: .72`、`--mc-grain-alpha: .018`）。
- 事实：这四组数字互不相等，且都不是 Mochi 的映射方式。按附录 A 落地，`.mc-glass` 实得 blur 12 / sat **1.7**（文档要 1.4，pack 没写 `--mc-sat`）；面板走 `--mc-blur-lg` = 20（文档要 28）；`alpha .72` 的面板 = `min(1,.72+.25)` = **.97**（文档要 86%）；玻璃底色是 `hsl(h, s*.4, 99%)`——**近白带色相，不是纸色**；暗色要的 14px 与 grain .035 需要一个单独的 `[data-mc-color-mode="dark"][data-mc-pack="stide"]` 块，附录里没有。另外原型 `<html data-mc-pack="stide">` 指向的包在 bundle 里**不存在**，等于这套令牌层从未被验证过。
- 建议定为：把层级收成两张表（组件 → 层；层 → 令牌），并补全 pack：

```css
[data-mc-pack='stide'],
[data-mc-pack='stide'][data-mc-color-mode='light'] {
  --mc-h2: var(--mc-h); --mc-h3: calc(var(--mc-h) - 34);
  --mc-blur: 20px; --mc-blur-lg: 28px; --mc-sat: 1.4; --mc-sat-lg: 1.5;
  --mc-glass-alpha: .72;
  --mc-glass-alpha-strong: .86;                                  /* 默认 .97，显式压到 86% */
  --mc-glass-bg: oklch(from var(--st-paper) l c h / .72);        /* 纸色，不是 99% 近白 */
  --mc-glass-bg-strong: oklch(from var(--st-paper) l c h / .86);
  --mc-grain-alpha: .018;
}
[data-mc-pack='stide'][data-mc-color-mode='dark'] {
  --mc-blur: 14px; --mc-blur-lg: 20px; --mc-grain-alpha: .035; --mc-glass-alpha: .78;
}
```

> `oklch(from …)` 需实测目标浏览器；不放心就退回 `color-mix(in oklab, var(--st-paper) 72%, transparent)`。关键点只有一个：**玻璃底色必须绑定纸色，并且随 hue 走**。
>
> 还有一个坑：Mochi 的亮/暗令牌块选择器是 `[data-mc-pack][data-mc-color-mode="light"]`（特异性 0,2,0，`tokens.css:427-429`），单写 `[data-mc-pack='stide']`（0,1,0）在亮色下会被它压过。pack 里覆盖 `--mc-glass-*` 时必须同时写 `[data-mc-pack='stide'][data-mc-color-mode='light']` 与 `…[data-mc-color-mode='dark']` 两份。

### P0-5 侧栏四选项（无 / 左 / 右 / 双）没有定义

- 位置：`02:293`（侧栏 无/左/右/双）+ `02:49-50`（左轨 76 是固定主导航）+ `01:164-168`（只有右侧栏的宽度账）+ `02:362-369`（响应式表也只有一个右栏）。
- 冲突：「左」到底是第二条内容侧栏，还是把 76px 图标轨关掉？「双」时宽度从哪来？原需求里的「单/双侧边栏」被映射成了四个选项，但没有一个选项有内容与栅格定义——这是当前唯一「点了会坏」的设置项。
- 建议定为（v1）：选项收成 **右栏 开 / 关**（默认开）；「左 / 双」移入 v1.1，并在 02 §9 加一行说明「左轨是导航，不参与侧栏布局」。如果坚持 v1 就做四选项，必须先给左栏内容（建议：人格在场 + 本月密度，200px）与三种栅格算式，否则不写。

### P0-6 布局宽度算不平

- 位置：`01:164-168`（≥1440：76 + 40 + 880 + 248 + 40 = 1284，1440 下剩 156 没交代）+ `02:366-367`（1024–1439：文章 688 + 目录 200，加上 76 + 32×2 = **1028 > 1024**，溢出 4px）+ 原型实测（首页 `max-width:1248`，内容列实际 ≈ 944；文章 688 + 224 居中；归档 1080）。
- 建议定为：外壳用「左轨 76 + 一个 max 1248 的居中容器」，容器内 `padding-inline: 40/32/24/20`，右栏 248/240；文章页容器 max 912（688 + 24 + 200 目录），1024 视口下目录折进文末 `<details>`。把 01 §5 的四行宽度账改成算式，别再写死 1284。

### P0-7 内容模型三处不一致（kind 阈值 / 图注字段 / 标签出口）

- kind：`02:336-341`（story = 有标题 **且** ≥600 字，推断顺序 link→photo→story→note）↔ `03:315-320`（有 title **或** ≥600 → story）↔ `03:156`（story 200–12000、note 1–600）↔ `03:392`（SKILL 说「不超过 800 字」）。四套阈值。建议定为一张表：**story 硬条件 = 有 title；600 字只用于「无 title 时的推断」**；note 1–600；story 200–12000（编辑可短于 200，发布器不管）。
- 图注：`02:338` 渲染「图注 1 行」，但 `03:109-113` 的 media 只有 `src/alt/width/height`，**没有 caption 字段** → photo 类型的核心排版无数据来源。建议在 media 项加 `caption?: string`（≤40 字），缺省用 alt。
- 标签：`01:17-18` 明文「标签不是装饰」，但全站没有 tag 路由、归档只按人格筛（`02:234`）、Pagefind 只索引正文（`02:273`）→ 标签既不能点也不能搜。建议二选一：**v1 砍掉标签**（三份文档同步删），或**加 `?tag=` + 归档筛选 + `data-pagefind-filter` 索引**。不要留着当装饰，那正好是 01 §11 要避免的东西。

### P0-8 多文件提交不原子：孤儿媒体 + 每篇两次构建

- 位置：`03:256`（先 GET 再 PUT，冲突重试 3 次）+ `03:544`（先写媒体再写文章，任一步失败即中止）+ `03:442`（`paths: content/**` 触发构建）。
- 冲突：媒体一次 PUT、文章一次 PUT = 两次 commit、两次 Actions；第二步失败留下无人引用的媒体；「提交即审计」被拆成两条不完整记录。
- 建议定为：改用 **Git Data API 单次提交**——`createBlob`（媒体）→ `createTree`（文章 + 媒体）→ `createCommit`（带全部 trailer）→ `updateRef`。一次提交、一次构建、要么全成要么全无。幂等键仍用 `Stide-Post-Id` + `Stide-Body-SHA256`。

### P0-9 agent 拿不到会话里的图，photo 类型实际上发不出来

- 位置：`03:349`（工具 `media?`：仓库路径或 https 图片）+ `03:254`（媒体若是 URL 先下载）。
- 冲突：QQ/微信里的图对模型只是一个消息元素，模型**不知道** URL，也无法传本地路径。按现设计，人格想发一张高达成品图，唯一办法是 owner 先手动 upload 进仓库——核心场景（photo）等于没通。
- 建议定为：插件在**服务端**解析当前消息链里的图片（`event.get_messages()` → `Image` 组件 → `await comp.convert_to_file_path()`，见 §3.5），下载到临时目录后交给 core；工具参数改成 `media: ["attachment:0"]` 这类**会话内引用**（拒绝任意 URL，顺带干掉 SSRF 面）。工具描述里明说「引用你刚发的图，不要编 URL」。

## 3. P1 · 动工前必须定（26 条，按文件）

**01 视觉语言**

1. `01:15` 规则「超过 2 行的可读文字不得放在 `backdrop-filter` 上」与设置抽屉、搜索结果（都是多行）直接冲突。改为：规则只约束 **L0 正文列**；浮层内容必须落在 ≥88% 实色底上（原型 `raised 88% + blur 28` 就是对的，把它写进规范）。
2. `01:185` 头像尺寸清单（20/32/36/120–160）与正文实际用法（18/20/24/28/36/56/72/160）对不上；`01:184`「2px 纸色外圈」vs `02:212`「3px」。建议给一套 8 档 token + 一张用途表，全站照抄。
3. `01:188`「列表里不出现封面缩略图」vs `02:338` photo 行有 240×135 图（原型 `css:298`）。请区分**封面 cover**（只有头条用）与**内容图**（photo 类型的正文首图），改一句话即可。
4. `01:225` 透明壁纸下「文章页自动回退到 full」——原型没有这条规则（`css:100-107` 只在 `.content` 上加玻璃）。要么实现，要么删；我建议保留（读长文时透明壁纸是干扰）。
5. `01:223` banner 顶部高度写 240，原型是 380（`css:619-626`）；`01:229-230` 光斑写 `h+32 / sat ≤55% / L ≥72%`，原型是 `h+38 / sat 62% / L 66%`。以原型为准改文档，别让实现方猜。
6. `01:229` 与原型都缺「暗色壁纸」参数（`01:230` 只给了一句 38% / .22）。四壁纸 × 两模式是 8 种，现在只定义了 4 种半。
7. `01:157` 字体四预置里「楷只加载 3500 字子集」与 `01:108-112`「不自托管 CJK 子集」语感冲突，且六语下 **ja / ko / ru 没有字体策略**（Noto Sans SC 不覆盖假名/谚文/西里尔）。建议：`--st-sans` 按 `:lang()` 分支，日/韩/俄各给一条系统优先栈；楷只对 `:lang(zh)` 生效。
8. `01:350` 字体预算「首屏 ≤2 个 woff2」与六语 + 四预置组合矛盾：切「楷」要新字体、切「俄语」要西里尔。改成「同一时刻 ≤2 个 woff2，切换字体时预加载」。

**02 页面与交互**

9. `02:101`（无媒体时头条标题可到 64px）与 `02:314`（404 用 96px）都不在 `01:121-129` 的字阶里。补 `display-lg 64` 与 `numeral 96` 两个 token，别在页面里随手写 px。
10. `02:117`「不做分页，静态输出全部」vs `02:325` 可配置「每页条数」。删配置项，或把它定义成「首屏渲染条数 + 其余靠归档」。
11. `02:19` `/people/<id>/rss.xml`、`02:216`「订阅她」都在 v1 页面里承诺单人格 RSS，但 `03:564` 把它排在 v1.1。要么进 v1，要么 v1 不渲染「订阅她」。
