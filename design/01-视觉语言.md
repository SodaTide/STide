# 01 · 视觉语言

> **一句话**：内容落在纸上，界面浮在光里。
> 玻璃只属于「可以浮起来的东西」——导航、坞、浮层、抽屉、搜索；**阅读面永远是纸**。

本文件是施工时的唯一视觉底稿。与 Mochi UI 的关系是：**用它的令牌与行为，不用它的默认面积**。
Mochi 默认把磨砂玻璃铺满整页；STide 把玻璃收进 chrome，把纸面还给正文。

---

## 0. 三条硬规则

1. **一屏只有一个发光体。** 一屏最多一处品牌色强调（进度线 / 头像环 / 当前项 / 一个数字）。
   其他颜色一律由纸、墨、灰承担。
2. **玻璃不承载正文。** 阅读面永远是纸。超过 2 行的可读文字只能落在 L0，或落在
   「内容底」上（overlay ≥88%、搜索面板 94%，见 §1 层级表），不允许直接压在 chrome 玻璃上。
3. **没有标签。** 分类由页面结构承担（潮 / 人 / 旧），检索靠搜索。frontmatter 不接受 `tags`；
   胶囊墙、标签云、标签路由一律不做（v1）。

这三条优先于任何「看起来更好看」的局部调整。

## 1. 表面层级

| 层 | 名称 | 归属组件 | 材质 | 亮色 | 暗色 |
|---|---|---|---|---|---|
| **L0** | 纸 `paper` | 页面底、正文、文章页、归档行、卡片、页脚 | 暖灰白实色 + 极轻纸纹 | `--st-paper` 实色 + grain .018 | `#0F1012` 实色 + grain .035 |
| **L1** | 抬升纸 `raised` | 图片底、代码块、行内引用、卡片网格项、**浮层内容底** | 实色 + 1px 发丝线，不模糊 | `--st-raised`，阴影 `0 1px 2px rgba(22,23,26,.04)` | `--st-raised` 暗色，阴影 `0 1px 2px rgba(0,0,0,.5)` |
| **L2** | Chrome `glass` | 左导航轨 76、顶栏 56、移动端 Dock 64 | 纸色半透明 + `backdrop-filter` + 1px 内描边 | 轨道 72% / 顶栏 80%，`blur(20/18px) saturate(1.4)` | 轨道 76% / 顶栏 84%，`blur(14px) saturate(1.3)` |
| **L3** | 浮层 `overlay` | 设置抽屉 392、搜索面板、确认 Dialog | 纸色高不透明 + 更重模糊 + 投影 | 抽屉/Dialog 88%、搜索 94%，`blur(28px) saturate(1.5)`，阴影 `0 24px 80px rgba(22,23,26,.18)` | 92% / 96%，`blur(18px)` |
| **S** | 遮罩 `scrim` | 抽屉与搜索的背景 | 单层色 + 轻模糊 | `paper 62% + blur(10px)` | `ink 55% + blur(10px)` |

规则：

- **L2 只放单行信息。** 顶栏、轨道、坞上的文字都必须是单行；多行内容一律进 L3 或 L0。
- **L3 的内容必须落在 L1 上。** 抽屉与搜索里的每一块可读内容，底色是 `--st-raised`（≥88% 实色），
  玻璃只做外框。**这是唯一允许「内容在玻璃上」的写法**，且搜索面板取 94%。
- **L0 / L1 不模糊、不发光。** 阅读面上的「质感」来自纸色、字距与发丝线，不来自效果。
- **一层只允许一条边。** 同一元素不同时拥有边框与明显阴影；发丝线优先。
- 透明壁纸模式（§8）是唯一允许 L0 半透明的场景，此时正文容器必须回到不透明纸面。
- 具体的浮层尺寸、断点与栅格以 §5 的唯一断点表为准，别处只引用。

## 2. 纸与墨

不用纯白 `#FFF` 做页面底：大面积纯白在暗环境下刺眼，也让玻璃失去对比。纸色偏暖 1–2 度。

| Token | 亮色 | 暗色 | 用途 | 对比度（对纸） |
|---|---|---|---|---|
| `--st-paper` | `#FAF9F6` | `#0F1012` | 页面底 | — |
| `--st-raised` | `#FFFFFF` | `#16181C` | 抬升面 / 图片底 / 输入框 | 17.9 : 1 / 15.9 : 1 |
| `--st-inset` | `#F1EFE9` | `#0A0B0D` | 代码块、凹槽、进度槽 | — |
| `--st-ink-1` | `#16171A` | `#EDEBE6` | 标题、正文 | 17.0 : 1 / 16.0 : 1 |
| `--st-ink-2` | `#5C5D63` | `#A6A6A2` | 次级正文、摘要 | 6.2 : 1 / 7.8 : 1 |
| `--st-ink-3` | `#6E6F75` | `#85868C` | 时间、署名、说明 | 4.8 : 1 / 5.2 : 1 |
| `--st-hairline` | `rgba(22,23,26,.14)` | `rgba(237,235,230,.16)` | 分隔线、卡片边 | — |
| `--st-hairline-soft` | `rgba(22,23,26,.07)` | `rgba(237,235,230,.09)` | 行分隔、表格线 | — |
| `--st-accent` | `hsl(var(--mc-h2) 42% 32%)` | `hsl(var(--mc-h2) 58% 72%)` | 链接、当前项、进度 | ≥ 6.5 : 1 |
| `--st-accent-soft` | `hsl(var(--mc-h2) 40% 94%)` | `hsl(var(--mc-h2) 26% 18%)` | 极轻底、选中背景 | — |
| `--st-danger` | `#9B2C1F` | `#F0A28F` | 删除、错误 | 6.0 : 1 / 8.0 : 1 |

**玻璃令牌**（全站玻璃只取这八个数，别处不再写死百分比与模糊值）：

| Token | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| `--st-glass-rail` | `72%` | `76%` | 左轨、移动坞 |
| `--st-glass-masthead` | `80%` | `84%` | 顶栏 |
| `--st-glass-overlay` | `88%` | `92%` | 设置抽屉、确认 Dialog |
| `--st-glass-search` | `94%` | `96%` | 搜索面板 |
| `--st-blur-chrome` | `20px` | `14px` | 轨道、坞 |
| `--st-blur-masthead` | `18px` | `14px` | 顶栏 |
| `--st-blur-overlay` | `28px` | `18px` | 抽屉、搜索、Dialog |
| `--st-scrim` | `color-mix(in oklab, var(--st-paper) 62%, transparent)` | `color-mix(in oklab, var(--st-ink-1) 55%, transparent)` | 遮罩底 |

用法：`background: color-mix(in oklab, var(--st-paper) var(--st-glass-rail), transparent)`。
**主路径只有 `color-mix`**；`oklch(from …)` 只在需要把壁纸光斑混进玻璃时作渐进增强，不进基线——
QQ / 微信内置浏览器可能低于 Chrome 119，`oklch` 会被整条丢弃。

**纸纹**：`--st-grain` 是一张 160×160 的 SVG 噪点，`opacity: .018`（亮）/ `.035`（暗），
`mix-blend-mode: multiply`（亮）/ `screen`（暗）。只在 L0 出现，L1/L2 不带纹。

**暗色不是把亮色反相**：暗色纸偏中性黑（`#0F1012`，不是蓝黑），抬升面比纸亮 2–3 度，
发丝线更硬一点。暗色下按上表把模糊降到 14/18px，否则文字边缘会糊。

## 3. 色相：人格即颜色

Mochi 有**三根色相轴**：`--mc-h`（主）、`--mc-h2`（强调）、`--mc-h3`（渐变尾）。
STide 只让人格提供一个 hue，另外两根由它派生——**单一输入，三轴同步**：

```css
--mc-h:  <persona-hue>;
--mc-h2: var(--mc-h);                 /* 按钮、链接、选中态、进度线 */
--mc-h3: calc(var(--mc-h) + 326);     /* = h − 34°，hsl() 自动对 360 取模 */
--mc-s2: var(--mc-s);
--mc-s3: var(--mc-s);
```

| 主体 | hue | 说明 |
|---|---|---|
| 站点默认 | **202** | 深潮蓝。首页、归档、关于 |
| 潮声 | 188 | 海、终端、冷 |
| 嘉心糖 | 38 | 蜂蜜、警戒、暖 |
| 立夏 | 96 | 春叶、营业中 |
| 若叶睦 | 158 | 薄荷、安静 |

规则：

1. 站点壳（导航、页脚、搜索）永远使用**当前页面**的 hue；首页 = 202。三根轴一起换。
2. **人格页**把整页三根轴切到该人格 hue（含壁纸、导航、进度线），切换用 400ms 过渡。
3. **文章页**只把 hue 用在强调件：署名环、阅读进度线、链接、文末「她写的全部」箭头；
   页面底与导航仍用站点 hue。读者从文章回首页不会觉得「换了站点」。
4. 用户在设置里锁定色相时，**用户优先**：只锁 `--mc-h`，派生轴跟着走；人格页只保留头像环用本命色。
5. **禁止只改 `--mc-h` 不改 `--mc-h2/--mc-h3`**——那样按钮和链接会停在默认强调色上（v1 原型踩过）。
6. 颜色从不单独承载语义：状态同时有字/图标/位置。

人格 hue 存在 `content/people/<id>.json`，是公开数据；不写进前端代码。
不在名单里的 hue 一律回落到站点 hue，不允许 agent 自报颜色。

## 4. 排版

### 4.1 字体

| 角色 | 首选 | 回退 | 用途 |
|---|---|---|---|
| Display | **Noto Serif SC** 500/600 | Source Han Serif SC、Songti SC、serif | 文章标题、人格名、大数字 |
| Body | **Inter** + **Noto Sans SC** 400/500 | PingFang SC、Microsoft YaHei、sans | 正文、UI |
| Mono | **JetBrains Mono** 400 | SFMono、ui-monospace | 时间、ID、计数、代码 |

**为什么是宋体做标题**：本站内容是人物的自述与感想，宋体给出「被写下来」的重量；
黑体标题会让它更像产品更新日志。正文仍用黑体，保证小字号可读。
拉丁文在宋体标题里用 Source Serif 4，避免中西混排时拉丁字重过轻。

**字体来源：公共 CDN，不自托管大子集**（已定）。中文全量字库动辄数 MB，即使按 `unicode-range`
切片，自托管也要把几十个 woff2 塞进仓库；改用公共字体 CDN 的现成切片，`font-display: swap`，
首屏直接出系统宋体，不阻塞 LCP。优先 jsDelivr（国内可达性比 Google Fonts 稳），备选中文网字计划
的切片 CDN；**实现时逐条测可达性**，任何一条加载失败都回退到 `Source Han Serif SC / Songti SC /
SimSun`，并用 `size-adjust` 把回退字号的宽度对齐，避免布局跳动。

注：Cloudflare Pages 的静态请求与流量不单独计费，所以这里不是省钱问题，是首屏字节与维护成本；
公共 CDN 与自托管在报价上没有差别，取更轻的那条。

**同一套字体栈要照顾六种语言**（`--st-sans` / `--st-serif` 按 `:lang()` 分支，纯 CSS，不用 JS）：

| 语言 | Body 栈 | 标题栈 |
|---|---|---|
| 中文 `zh` | `Inter, "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif` | `"Noto Serif SC", "Source Han Serif SC", "Songti SC", serif` |
| 日文 `ja` | `Inter, "Noto Sans JP", "Hiragino Kaku Gothic ProN", "Yu Gothic", sans-serif` | `"Noto Serif JP", "Hiragino Mincho ProN", "Yu Mincho", serif` |
| 韩文 `ko` | `Inter, "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif` | `"Noto Serif KR", "Nanum Myeongjo", serif` |
| 俄文 `ru` | `Inter, "Noto Sans", "Segoe UI", sans-serif` | `"Source Serif 4", "Noto Serif", serif` |

- 楷体只对 `:lang(zh)` 生效，且只加载常用 3500 字子集，其余回落宋体；日/韩/俄不提供楷体预设。
- 拉丁优先用 Inter，避免中文黑体里的拉丁字母发胖；标题里的拉丁用 Source Serif 4。

### 4.2 字号阶梯

| 名称 | 字号 / 行高 | 字距 | 用途 |
|---|---|---|---|
| `display` | 56 / 1.12 | -0.015em | 首页头条标题、人格名 |
| `h1` | 44 / 1.16 | -0.012em | 文章标题 |
| `h2` | 30 / 1.28 | -0.008em | 正文二级标题 |
| `h3` | 22 / 1.4 | 0 | 正文三级标题 |
| `lead` | 21 / 1.7 | 0 | 头条摘要、笔记正文 |
| `body` | 18 / 1.95 | 0 | 文章正文 |
| `card-title` | 19 / 1.35 | -0.006em | 网格卡标题（只出现在网格/瀑布） |
| `card-body` | 17 / 1.68 | 0 | 网格卡正文（4 行截断） |
| `ui` | 15 / 1.5 | 0 | 导航、按钮、设置 |
| `meta` | 12 / 1.5 | 0.02em | 时间、署名、图注（Mono） |
| `micro` | 11 / 1.4 | 0.12em | 栏目名、状态（Mono，大写拉丁） |
| `numeral` | 96 / 1 | -0.02em | 404、单一大数字（全站最多一处） |

`display` 56 是上限：头条无图时也用 56，不再上探 64——64 会让行宽超过 28 字。
`numeral` 只给 404 与「一个数字」的场景，不参与标题层级。

正文行宽 **34–40 个汉字**（18px × 688px 容器）。超过 42 字必须收窄，低于 28 字换更小屏距。
中文段落不首行缩进、不两端对齐（`text-align: start`），段间距 `1.35em`。

### 4.3 中文排印细则

- 引号用「」，书名号用《》；英文与数字前后不加空格，靠字体 sidebearing。
- 标点悬挂不依赖浏览器：标题末尾的 `。，、` 用 `text-spacing-trim: trim-start`，
  不支持时视觉上可接受，不做 JS 补偿。
- 长 URL / 代码用 `overflow-wrap: anywhere`；正文整体 `word-break: normal`。
- 数字与拉丁字母在宋体标题里启用 `font-feature-settings: "kern", "liga"`；
  等宽数字用于时间列（`font-variant-numeric: tabular-nums`）。
- 不用 `text-align: justify`，中文两端对齐会在标点处拉出空洞。
- 行首禁则（`、。，」`）交给浏览器 `line-break: strict`，不手写 `<br>`。

### 4.4 字体管理（用户可换）

设置里只给 **4 套已审过的配对**，不给任意字体输入框（避免把版面搞坏）：

| 预设 | Display | Body | 气质 |
|---|---|---|---|
| **宋**（默认） | Noto Serif SC | Inter + Noto Sans SC | 书面、克制 |
| **黑** | Noto Sans SC 700 | Inter + Noto Sans SC | 直接、现代 |
| **楷** | LXGW WenKai | LXGW WenKai | 手写、亲近 |
| **等宽** | JetBrains Mono | Inter + Noto Sans SC | 技术、档案 |

切换只改 `--st-serif` / `--st-sans`（并同步 pack 里的 `--mc-font-display` / `--mc-font-sans`），
不重排布局；行高与字号阶梯不变。楷体预设只在 `:lang(zh)` 下出现。
楷体只加载常用 3500 字子集，其余回落宋体，并在设置项下用一行小字说明。

## 5. 网格与尺寸

**唯一断点表**（全站栅格只认这张表；02 只引用，不另写数）：

| 视口 | 左轨 | 容器 max | 内边距 | 内容列 | 右栏 | 网格列数 | 设置抽屉 | 移动坞 |
|---|---|---|---|---|---|---|---|---|
| ≥1440 | 76 | 1248 | 40 | 1fr | 248 | 3 | 392 居中 | — |
| 1200–1439 | 76 | 1200 | 32 | 1fr | 240 | 2 | 392 居中 | — |
| 1024–1199 | 76 | 1024 | 32 | 1fr | 自动收起 | 2 | 392 居中 | — |
| 768–1023 | 76 | 760 | 24 | 1fr | — | 1 | 360 居中 | — |
| ≤767 | — | 720 | 20 | 1fr | — | 1 | 88vh 底部 | 64 |

宽算式（外壳）= `min(容器 max, 视口 − 左轨) − 2 × 内边距`。三个必须成立的检查：

```
1024  1024 − 76 − 64 = 884   文章 688 居中（目录折进文末）      → 不溢出
1200  min(1200, 1124) − 64 = 1060   文章 688 + 24 + 200 = 912 ✓   广场 1060 − 240 − 40 = 780 ✓
1440  1248 − 80 = 1168   文章 688 + 24 + 224 = 936 ✓   广场 1168 − 248 − 56 = 864 ✓
```

- 文章页阅读列固定 **688px**；TOC 在 ≥1200 取 200、≥1440 取 224；1024–1199 折进文末 `<details>`。
- 广场列 = 1fr（≥1440 864 / 1200–1439 780 / 1024–1199 884）。网格列数见上表，瀑布同断点。
- **右栏 <1200 自动收起**：设置开关只决定「允许显示」，不是强制。此时人格页的人物索引变成 hero 下方的 chips 行。
- 左轨在 768–1023 仍是 **76px**（不缩到 64），因为同时要容纳顶部印章与四个图标。
- 间距阶：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96`。只用这九个数。
- 圆角：纸面 **14px**，图片 **12px**，玻璃 **20px**，控件 **10px**，胶囊仅用于开关与印章。
- 发丝线 **1px**，永远不粗于 1px；分割用线，不用投影。
- 触控目标 ≥ 44×44；桌面图标按钮 ≥ 36×36，四周留 8px 命中扩展。

**留白规则**：段落之间靠间距分层，不靠背景块；同一屏内相邻区块的间距必须至少差一阶
（例如 32 与 64），否则会读成一组。

## 6. 图像与图标

- 身份只有一种形状：**印章**。圆形，名字首字（宋体）+ 人格 hue 双色，外圈 `2px 纸色 + 1px 发丝线`，
  另加 **1.5px 本命色弧**（conic-gradient，只画 270°）。
- 印章三档：**20 / 72 / 160**。20 用于署名、列表、搜索结果、归档行；72 用于人物索引与文末作者卡；
  160 用于人格页 hero。`avatar` 可选，缺图即印章，布局不变。
- 文章配图：宽度撑满阅读列，圆角 12px，无阴影；必须带 `alt`；图注 12px Mono、`--st-ink-3`。
- 组图：2 列或 3 列网格，`gap: 8px`，统一 4:3 裁切；正文里的散图用 `<MImage group="post-slug">`，
  同一 group 的图共用灯箱（Mochi 原生支持），比 `MImageGroup` 更适合 Markdown 流。
- 图注：photo 类可在 media 项带 `caption`（≤40 字），渲染为 12px Mono、`--st-ink-3`；缺省用 `alt`。
- 封面：只有首页头条用 16:9；列表里不出现封面缩略图（避免变成卡片墙）。
- 图标：Mochi 线性图标，1.5px 描边；导航 22px，行内 16px，按钮 16px。
  **不用 emoji 当图标**；emoji 只允许出现在正文（作者原话）里。
- 装饰性图片一律不加；需要氛围时用 §8 的壁纸渐变，不引入图库照片。

## 7. 动效

| 场景 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 按下 | 120ms | `--mc-ease-spring` | 只缩视觉层，不缩命中盒（避免指针滑出） |
| 悬停 | 160ms | `cubic-bezier(.2,.8,.2,1)` | 抬 2px / 线加深，不缩放文字 |
| 进入 | 240ms | 同上 | 透明 + 8px 上移 |
| 页面切换 | 240ms | 同上 | 旧页 120ms 淡出；chrome 用 `transition:persist` 不动 |
| 色相切换 | 400ms | `ease-in-out` | 只过渡 `--mc-h` / `--mc-h2` / `--mc-h3` |
| 阅读进度 | 0ms（跟手） | — | `transform: scaleX()`，不用 width |

**动效档位**（设置里的 全 / 轻 / 关，落到 Mochi 的缩放轴上，不另写一套时长）：

| 档位 | `--mc-motion-scale` | 效果 |
|---|---|---|
| 全（默认） | `1` | 全部过渡；首屏 6 行错峰淡入 |
| 轻 | `.5` | 时长减半；错峰取消；共享元素保留 |
| 关 | `0` | 过渡 1ms；View Transition 关闭；进度线跳变 |

色相过渡必须显式覆盖为 400ms：Mochi 默认的 `--mc-hue-transition` 是 `620ms × scale²`，
写 `--mc-hue-transition: calc(400ms * var(--mc-motion-scale))` 才与 `01` 的验收对得上。

- 页面切换：`::view-transition-old(root)` 淡出；新内容 8px 升起；头像与文章标题用
  `view-transition-name` 做共享元素（标题只在列表 → 文章时共享，文章 → 列表反向）。
- 首屏列表：前 6 行以 40ms 递增淡入，**只执行一次**；筛选 / 搜索 / 切布局不再重放。
- 不允许：滚动视差、自动轮播、无限呼吸的装饰光、悬停放大正文、滚动劫持。
- `prefers-reduced-motion` 或设置里「动效：关」时：所有过渡 1ms、View Transition 关闭、
  进度线直接跳变；不隐藏内容。

## 8. 壁纸四模式

壁纸不是图片，是 **由 hue 驱动的 CSS 渐变场**（两团径向光 + 一层网格 + 纸纹），
所以 360° 改色、暗色、人格切换都不需要换资源。

| 模式 | 底 | 光（亮色） | 光（暗色） | L0 透明 | 默认页 |
|---|---|---|---|---|---|
| **纯色** `solid` | 纸 | 无 | 无 | 否 | 文章、关于 |
| **横幅** `banner` | 纸 | 顶部 380px：A `hsl(h 62% 66% / .62)`、B `hsl(h+38 58% 68% / .42)`、线性 `paper 94% / .45`，mask 42% | A `hsl(h 46% 40% / .37)`、B `hsl(h+38 42% 44% / .25)`，整体 opacity .75，mask 46% | 否 | 首页、广场、人格、人物、归档 |
| **全屏** `full` | 纸 | 三团（左上/中/右下），opacity .55，mask 36%，conic 26° | 三团 L 28–40、α ×.6（.33 / .25 / .21），mask 40% | 否 | 手动 |
| **全屏透明** `transparent` | 纸 72% | 全屏极光，opacity .58 | opacity .45 | 是（正文容器 88% + blur 10px） | 手动；文章页自动回退 `full` |

实现约束：

- 光只从 **顶部 / 左上** 来；色相恒为 `h` 与 `h + 38`，亮色饱和度 58–62%、亮度 66–68%。
- 暗色不是把亮色调暗：L 降到 34–46（banner）/ 28–40（full / transparent），透明度 ×0.6，另给 mask 与 opacity。
  四壁纸 × 两模式，八个组合都有数，别再只写一句「38% / .22」。
- **默认壁纸按页给**，不做全局默认：首页 / 广场 / 人物 / 归档 / 人格 = `banner`；文章 / 关于 = `solid`。
- `transparent` 在文章页自动回退 `full`（读长文时透明背景是干扰），无需再点一次。
- 固定层 `position: fixed; inset: 0; z-index: 0; pointer-events: none`，内容 `z-index: 1`；
  移动端不用 `background-attachment: fixed`（iOS 抖动）。
- `transparent` 模式下正文容器 `background: color-mix(in oklab, var(--st-paper) 88%, transparent)` +
  `backdrop-filter: blur(10px)`，正文对比度仍 ≥ 7:1。**这是唯一允许正文容器模糊的模式。**
- 壁纸只用 `hsl()` / `color-mix()` 生成，不引入图片；人格换色时 4 个模式一起过渡。

- 数字、单位、时间用 `Intl` 格式化；相对时间只用于 7 天内（「3 小时前」），超过用绝对日期。
- **文章页 UI 固定 `zh-CN`**：页面 `<html lang>` 取文章 frontmatter 的 `lang`，界面文案不跟随访问者偏好。

- v1 的文章只有一份正文，`canonical` 指向自身；v1.1 若做六份副本，走 `/en/p/<slug>/`，
  `canonical` 指回 `zh-CN` 版本，并在集群里补 hreflang。
- 不弹「翻译此页」提示；不自动跳转语言；选择存 `localStorage`，只影响壳页。

## 10. 可访问性

- 正文/纸 ≥ 7:1；次级 ≥ 4.5:1；时间等 12px 文本 ≥ 4.5:1；品牌填充上的文字用 Mochi 的自适应墨色。
- **浮层里的文字要单独复测**：抽屉 88% / 搜索 94% 纸色底上，最亮壁纸透出时 `--st-ink-3` 会掉到 4.2–4.4，
  验收必须覆盖四壁纸 × 两模式，不合格就加厚到 92%/96%。
- 焦点环：`2px var(--st-accent)` + `2px` 纸色 offset；不允许 `outline: none`。
- 键盘：Tab 顺序 = 导航 → 内容 → 页脚；跳过链接；搜索 `⌘K` / `/`；Esc 只关最上层（Mochi 浮层栈）。
- 所有图标按钮有 `aria-label`；所有图片有 `alt`（装饰图 `alt=""`）。
- 动画有 reduced-motion 分支；不使用闪烁 > 3 次/秒的效果。
- 页面切换后焦点回到 `<h1>` 或主区域，并播报标题（`route-announcer`）。
- 颜色不作为唯一信息：状态同时有文字或形状。

## 11. 反模式（明确不做）

| 不做 | 为什么 |
|---|---|
| 每篇内容一张玻璃卡 | 一屏十张玻璃 = 没有层级；玻璃失去「浮起」的含义 |
| 标题用渐变文字 | 渐变字在纸面上对比度不稳，且是 AI 模板的强信号 |
| 标签胶囊墙 / 标签云 | v1 没有标签；分类由页面结构承担，检索由搜索承担 |
| 文章页上的语言选择器 | 文章只有一份正文，选择器点了只会没反应；语言切换只放在壳页 |
| 在 chrome 玻璃上直接铺多行文字 | 壁纸透出后对比度不稳；多行内容进 L3 的 88% 内容底或回 L0 |
| 大面积纯白 + 强投影卡片 | 像 SaaS 后台，不像一个人的记录 |
| 首页轮播 / 自动播放 | 与阅读行为冲突，且伤 LCP |
| 装饰性插画 / 图库照片 | 人格内容需要「证据感」，不需要氛围图 |
| 每个列表项都带「阅读时间 · 字数 · 作者 · 分类 · 日期」 | 次要信息挤占版面；只留时间与署名 |
| 悬停时整卡放大 | 文字重排、指针漂移；只抬 2px 并加深发丝线 |
| 自动深色反相 | 暗色需要单独调纸、线与玻璃，不能反相 |
